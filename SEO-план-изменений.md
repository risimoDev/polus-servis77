## 0. Сверка аудита с фактическим кодом (читать первым)

### 0.1. Что аудит считает сломанным, но в репозитории УЖЕ сделано

| Пункт аудита | Реальное состояние в репозитории |
|---|---|
| «Услуги рендерятся на клиенте, в HTML пустой шаблон» | **Есть prerender-пайплайн (SSG).** [scripts/prerender-services.cjs](scripts/prerender-services.cjs) генерирует статические [service/*.html](service/) (6 страниц, 35–37 КБ каждая) с готовым контентом в `<body>`. Nginx отдаёт их по `/service.html?id=<slug>` через `map` в [nginx/nginx.conf](nginx/nginx.conf#L39-L46) |
| «Title/Description услуг одинаковые» | **Уникальны.** У каждой `service/*.html` свой Title и Description (проверено) |
| «canonical услуг → service.html (кросс-канонический)» | **Self-canonical.** В `service/promyvka-teploobmennikov.html` canonical = `service.html?id=promyvka-teploobmennikov` — совпадает с URL, по которому nginx отдаёт файл |
| «Schema.org не обнаружена (Fail)» | **Внедрена широко.** index.html: `LocalBusiness`, `Service`×3, `FAQPage`, `Offer`×3, `OfferCatalog`, `PostalAddress`, `ContactPoint`, `OpeningHoursSpecification`. service-страницы: `+BreadcrumbList` |
| «Нет отдельных URL услуг, только якоря #services» | Реальные URL услуг есть (`/service.html?id=…`), контент отдаётся сервером |

**Вывод:** аудит проверял, судя по всему, версию сайта **до деплоя prerender/schema** (файлы в репозитории от 23–24 июня). Значит, критический пункт №1 плана — не «переписать рендеринг», а **убедиться, что prerender реально задеплоен на прод** (см. 1.1).

## 1. Критический блок (сделать в первую очередь)

### 1.1. Подтвердить деплой prerender услуг на прод
- Открыть в браузере «view-source» для `https://polus-servis77.ru/service.html?id=promyvka-teploobmennikov` и убедиться, что в **исходном HTML** (не после JS) есть H1, текст, шаги, FAQ и canonical с `?id=`.
- Если там пустой шаблон — **выполнить деплой** (пересобрать prerender и залить `service/` + `nginx/nginx.conf`):
  1. `node scripts/prerender-services.cjs`
  2. Залить каталог `service/` и `nginx/nginx.conf` на сервер, перезагрузить nginx ([scripts/nginx-reload.sh](scripts/nginx-reload.sh)).
- Добавить npm-скрипт `"prerender": "node scripts/prerender-services.cjs"` в [package.json](package.json), чтобы шаг не терялся.

### 1.2. Исправить canonical и prerender каталога категорий
- Сейчас `catalog.html?cat=280/281/359` отдаётся клиентским шаблоном с общим Title «Каталог комплектующих — Полюс Сервис» и без self-canonical на `?cat=`.
- По аналогии с услугами: **сделать prerender категорий** (новый скрипт `scripts/prerender-catalog.cjs`, шаблон-оболочка `catalog.html`, источник `assets/data/catalog.json`), nginx-`map $arg_cat → /catalog/<cat>.html`.
- Для каждой категории: уникальный Title/H1/Description, self-canonical на `catalog.html?cat=<id>`, `BreadcrumbList`.

## 2. Каталог — главный оставшийся актив (стратегическое, на квартал)

Единый скрипт-генератор `scripts/prerender-catalog.cjs`, читающий [assets/data/catalog.json](assets/data/catalog.json) (8,2 МБ). Поэтапно, с контролем «тонкого» контента.

### 2.1. Категории (3 шт.) — быстро
Пластины / Уплотнения / Теплообменники. Prerender + уникальные мета + перелинковка вниз к брендам. *(Пересекается с 1.2.)*

### 2.2. Страницы брендов (~26 брендов × 2–3 категории ≈ 50–70 страниц)
- URL: `catalog.html?cat=280&brand=ridan` → prerender в `catalog/plastiny/ridan.html` (или ЧПУ, см. 6.2).
- Уникальные Title («Пластины Ридan — купить в Перми, цена»), H1, вводный абзац 100–200 слов, листинг позиций бренда.
- Запросы «пластины Ридан», «уплотнения Alfa Laval», «пластины Sondex» — низкоконкурентные, транзакционные.
- Заготовки описаний уже есть в [assets/data/](assets/data/) (md-файлы по номенклатуре) — использовать как источник текста.

### 2.3. Карточки товаров (поэтапно)
- **Фаза 1:** открыть для индексации только **топ-500 ходовых артикулов** с уникальным Title («Уплотнение Alfa Laval M10 — купить, цена») + `Product`/`Offer` schema.
- **Фаза 2:** расширять пачками, мониторя в Вебмастере «Страницы в поиске» на предмет фильтра за малополезные.
- Остальные ~69 000 — до готовности держать через листинги брендов/категорий, не плодить тонкие страницы.

### 2.4. Alt изображений товаров/логотипов
Переименовать хэши файлов в транслит по мере генерации (`plastiny-ridan.webp`), проставлять осмысленный alt.

## 3. Гео и доверие (Пермь) — быстрые, высокий эффект

### 3.1. Добавить физический адрес + карту
- Блок «Контакты» на главной и в подвале: реальный адрес офиса/склада в Перми + виджет Яндекс Карт.
- Внести `streetAddress` в `PostalAddress` schema (сейчас там только город/регион).

### 3.2. Карточки в справочниках
- Завести/подтвердить **Яндекс Бизнес** и **2ГИС** по **Перми и Москве** (две точки; без этого гео-ранжирование в Яндексе почти невозможно). Синхронизировать адрес/телефоны/часы с сайтом.
- Добавить `sameAs` (VK, Telegram) в LocalBusiness schema.

### 3.3. Google Search Console
- Подключить верификацию (метатег/DNS), загрузить sitemap. Яндекс.Вебмастер уже подключён.

### 3.4. Расширить гео в Schema.org и текстах
- В `LocalBusiness`/`Service` schema указать `areaServed` = **Пермь и Москва** (сервис), а для каталога/продаж — `areaServed` = «Россия» с приоритетом Пермь+Москва.
- Если есть вторая точка (Москва) — добавить второй адрес/филиал или `Organization` с несколькими `location`.
- В текстах услуг («…Пермь») добавить упоминание Москвы там, где сервис реально оказывается.

### 4.1. Текстовые дефекты
- Исправить опечатку **«близжайшее» → «ближайшее»** — в 12 файлах (index, service.html, все service/*.html, catalog и др.). Поправить в исходном шаблоне модалки и перегенерировать prerender.
- Убрать/дописать **«Монтаж (скоро…)»** в [index.html](index.html) и [assets/data/services.json](assets/data/services.json).

### 4.2. Alt логотипов производителей

### 4.4. Цены «от…»

### 4.5. Core Web Vitals

## 6. Технические доработки

### 6.1. robots.txt / sitemap
- Добавить в [robots.txt](robots.txt): `Clean-param: id&cat&brand` (для Яндекса, чтобы не плодить дубли по параметрам).
- Расширять [sitemap.xml](sitemap.xml) по мере генерации страниц брендов/товаров. Проставлять реальный `lastmod` (сейчас у всех одинаковый).
- Проверить редирект `index.html` ↔ `/` (в шапке внутренних страниц ссылки на `/index.html`, canonical главной — на `/`): настроить 301 `/index.html → /`.

### 6.2. ЧПУ (по возможности, не блокирует)
- Перевести на человекопонятные URL: `/uslugi/promyvka-plastinchatyh-teploobmennikov/`, `/catalog/plastiny/ridan/`. Настроить 301 со старых `.html?param=`.
- Не критично: nginx уже маршрутизирует `?id=` на статику, индексации это не мешает. Делать при рефакторинге каталога.

### 6.3. Проверить 404 и битые ссылки
- [404.html](404.html) есть; убедиться, что nginx/Apache отдают её кодом 404. Проверить внутренние ссылки на `/index.html`.
